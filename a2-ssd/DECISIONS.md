# A2 SSD Platform — build decisions (Opus 5.5 build window, 27 Sep 2026)

Each line: the call, why. SPEC §12 and the accepted prototype win over earlier SPEC sections.

D1 · Worktree ~/Sites/ols-wt-a2 on branch a2-ssd-build (from origin/main 05ee12d). The main checkout stays on its own branch so no other window is disturbed (standing rule: leave other windows' folders alone). Never under /tmp.
D2 · The repo is PUBLIC (gh: visibility PUBLIC). Anything in it is on github.io. So the answer-bearing sources — judge/ (judge.js, markpoints.js, twinpoints.js, controls.js) and the content with models (papers.json model/msPoints, twin models) — live PRIVATELY in "Claude Work/A2 SSD Platform/src/" (the KS3 content-src pattern). The repo a2-ssd/ holds seeds, tools, gates, the public content the packer emits, the platform and the server. First-actions step 4 was done literally (copied into a2-ssd/, 484 GREEN), then moved to src/ before any commit. Gates read src via A2SSD_SRC (default that path).
D3 · The judge runs on the server only. pack-content.js bundles judge.js + markpoints.js + twinpoints.js + every exam model + every twin model into one script, encrypts it with A2SSD_SECRET, and writes it into the server source as a string. Code.gs decrypts it once per execution (cached in CacheService per build) and evaluates it. The client never holds a detector or a model; Show the examiner's answer asks the server. Keystream: SHA-256(secret|file) once, then a pure-JS xoshiro128** stream (Utilities.computeDigest per 32-byte block would cost seconds per call on a 150 KB bundle).
D4 · Public content (papers without model/msPoints, mark-point labels + marks + habits, lessons, twin questions + tables, strings) is INLINED into the served page at build time, not fetched: one deploy = one consistent set, no CORS, no stale cache. The server stamps BUILD into the page; every call carries it; a mismatch answers `stale` and the page shows the SPEC §3.9 reload line. Seeds and sql.js are served from github.io (sql.js vendored into a2-ssd/platform/vendor).
D5 · Every pupil/teacher string lives in content/strings.json (from SPEC §3 and the accepted prototype, each with its source) or in the paper/lesson/twin content. Client code holds no pupil-visible literal. G4 enforces it.
D6 · Lessons carry per-step `need:[skill]`. A part's lesson shows only the steps whose skills its mark points use (a step with no `need` always shows). The worked statement is modelled as tagged lines and assembled at render; commas between fields are added structurally, so a hidden step never leaves a dangling comma. G1/G5 check each part's visible steps against its mark points.
D7 · CREATE splits in two lessons: CREATE (Tinies set 1, CHILD — name, fields, PK, NOT NULL, composite-key shape, FK) serves 2015-1, 2016-1, 2022-a; CREATE-RULES (set 2, STOCKORDER — IDENTITY, DEFAULT GETDATE(), NOT NULL, CHECK, FK) serves 2023-a, 2026-b, 2018-a. One shared aggregates lesson serves GROUP-COUNT and GROUP-SUM.
D8 · Twin tables re-targeted so no twin re-serves a lesson's worked table: T-CREATE-2 → ATTENDANCE (set 3), T-CREATE-3 → SESSIONBOOKING (set 4) (see F6).
D9 · The judge reads every script six ways (plain; quote repair; requote of bare values; both; SELECT aliases without AS; "double-quoted" names as identifiers) and each point takes its best reading. A punctuation slip therefore can never cost a mark while a content fault (wrong field, table, value, missing clause) still does, because no reading invents content. Bracket repair works on the statement's own words: a bracket is closed where the group's word says it ends (a type size, a key column list, GETDATE's empty brackets) and opened where a word needs one; the must-cost half of G1 proves the repairs never give content marks away.
D10 · G1 must-cost exemptions only where the CCEA scheme itself gives no mark for the thing removed: 2016-1 table name, 2016-2 FROM, 2019-c ORDER BY (GROUP BY also earns it). Each is written in g1-judge.js with its reason.
D11 · Answer-space controls (5 right / 5 partial / 5 wrong per mark point) are written by SEPARATED Sonnet readers from the verbatim CCEA scheme, never shown the engine (gates/answerspace/RULES.md, private). Every disagreement with the engine is adjudicated against the scheme: engine harsher → engine fixed + control; reader wrong → control corrected with the reason; note over-promises → note fixed. The adjudicated set becomes judge/answerspace.json and runs inside G1.
D12 · Expected rows are computed LIVE, never stored. Seeds date themselves from today, so a precomputed expected/*.json goes stale overnight (F13). The server's `mark` reply carries the model SQL for the paper ("turn") only, never for Another question; the client runs the shimmed model on a fresh copy of the seed to fill Expected rows and Same rows / Different rows. The model text is never displayed until Show the examiner's answer (showAnswer, which sets saw-answer). expected/*.json dropped.
D13 · G2 re-dates every seed by replacing 'now' with nine anchors (today, 2026-01-01, 01-31, 03-01, 03-31, 06-30, 09-01, 12-31, 2028-02-29): month ends, year ends, a leap day and a short month. Every SELECT model must return ≥1 row on each. "This month" rows use max(date('now','-N days'), date('now','start of month')); "last month" rows use 'start of month','-1 month','+N days' with N < 28.
D14 · The Tinies twin sets get their own seeds (seeds/tinies-1.sql … tinies-4.sql), table-for-table with twins.json, each with traps beside the rows the answer wants. Set 5 (DAYTRIP) is CREATE only: no seed; G2 builds its model on an empty database.
D15 · Every TEXT column is COLLATE NOCASE, so 'tinies 2' finds 'Tinies 2' as SQL Server's default collation does.
D16 · Papers with no GETDATE question keep their printed dates (2016, 2017); only date-relative questions get date('now', …) seeds.
D17 · Mark-scheme spellings that differ from the printed tables run as views: STAFF_SPECIALTY (2024), BOOKINGS (2025), SUPSTOCKORDERDETAILS (2026). Either spelling runs in SELECT; the DATA tab lists only the printed table.
D18 · The DATA tab hides whatever the part asks the pupil to make. pack-content derives `hides` from the model: CREATE → that table (2015-1 DIVE, 2016-1, 2018-a CONTRACT, 2022-a, 2023-a and 2026-b SUPPLIERSTOCKORDER); ALTER … ADD → that column (2024-c-i STAFF.StartDate).
D19 · Result grid headers copy SSMS: a column that is not a plain name or an alias shows "(No column name)" (FirstName || ' ' || Surname, COUNT(SalesNo)). Same rows compares values in order, never column names. G5 checks both.
D20 · Lookup tables keep their real size (2 sites, 4 areas); G2 asks for ≥1 row, not SPEC §6's "8–20".
D21 · The shim's DATEADD month/year clamps to the month's last day as SQL Server does (31 Mar − 1 month = 28 Feb; 29 Feb 2028 + 1 year = 28 Feb 2029), where SQLite's own modifier overflows into the next month.
D22 · Canonical copies: a2-ssd/seeds and a2-ssd/tools/tsql2sqlite.js in the worktree. The design folder keeps copies with a README pointing here.
D23 · Table prefixes: strict only inside a join equality (a prefix naming a table not in the FROM, or a field compared with itself, loses the join mark); everywhere else an unknown or wrong prefix is a slip and is dropped (ruling 13: prefixes never cost). A field followed by arithmetic (SET STOCK.Price = STOCK.Price * 1.1) is a calculation, never a join.
D24 · Field ownership (points saying "from two or more tables") follows D23: a known prefix names its table; a bare or slipped field belongs to whichever FROM table holds it; a partial answer with no FROM yet looks across the paper's tables, so it reads as far as it goes.
D25 · Rulings settled while running the six reader answer sets (gates/answerspace, 3,135 controls): LIKE with no wildcard = equals; LEFT JOIN where INNER is printed keeps the join marks (2016-2 rows are the same); INSERT without INTO and INSERT…SELECT keep the marks; two inline PRIMARY KEYs is not a composite key (0 with a note); a 2026-d ON condition without the alias keeps the mark with a note; COUNT counts a field of the right table or *; clauses in any order read; DATEDIFF(day…)=0 for "today" is right; 2024-d takes the strict forms MARK_POINTS lists (> 5, < DATEADD); TODAY + 1 stays right for 2021-b (MARK_POINTS line 242); a misspelt field name costs (it is a wrong field); a comma or semicolon in place of AND in a WHERE loses the pairing mark (it is a missing clause, not punctuation); a hard-coded past year in 2022-d loses the "this year" mark, the current year keeps it with a note. Each is in gates/answerspace/adjudicated.json (40 entries) with its reason, and G1 step 6 fails on any new disagreement.
D26 · 2025-b: the total may be SUM(Duration)/60, SUM(CAST(Duration AS …))/60 or CONVERT; ORDER BY must be the total hours DESC (ordering by the count loses that point). "Next week" = the 7 days from one week ahead, in any of the date forms MARK_POINTS lists.
